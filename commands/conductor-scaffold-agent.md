Scaffold, test, run, deploy, and wire up a Conductor Agent using [skills/conductor/references/agents.md](../skills/conductor/references/agents.md) (contract, lifecycle, decision table, HITL, operations) and [skills/conductor/references/agent-sdks.md](../skills/conductor/references/agent-sdks.md) (language × framework matrix, install/import per cell, scaffolds). The walk-through is [skills/conductor/examples/agent-deploy-and-invoke.md](../skills/conductor/examples/agent-deploy-and-invoke.md).

A Conductor Agent is code you author with an SDK (or bring from a framework) that the server **compiles into a workflow** named after the agent. Prefer it over hand-wiring a `DO_WHILE` ReAct loop — the compiler owns the loop, tool routing, guardrails and HITL. Check the "Which path?" table in agents.md §2 first: if the user actually wants a fixed LLM/MCP pipeline (path 1) or a remote A2A agent (path 4), stop and use that path instead.

## Procedure

0. **Preflight — fixed order, stop on failure.**
   1. `conductor workflow list` — server reachable? If not, run `/conductor-setup` first.
   2. `conductor agent list` — a table or `No agents found.` means the agent runtime is on. A 404 / HTML / connection error means `conductor.integrations.ai.enabled` or `agentspan.embedded` is off (local `conductor server start` enables both; for a remote server the admin sets them). **Stop here if it fails** — an `AGENT` task with `agentType: "conductor"` on such a server fails with the misleading `AGENT requires 'agentUrl'`.
   3. `python3 "$CONDUCTOR_API" providers-status` — pick a `provider/model` whose provider is `configured: true` (Gemini prefix is `google_gemini/`). If none is configured the fix is a provider key **on the server**, never in agent code. Never echo key values.
1. **Ask for language.** Python, TypeScript / JavaScript, Java, C#. Default to the dominant language of the open repo, but confirm. C# agent packages are a preview (project reference, not yet on NuGet).
2. **Ask for framework, constrained by language** (matrix in agent-sdks.md §4). Offer "Conductor SDK (native)" first — richest tool / guardrail / testing surface. If the user names a cell that does not exist for their language, say so with the exact message in agent-sdks.md and offer the nearest supported cell; never improvise a bridge.
3. **Ask what the agent does.** Collect `name` (snake_case or kebab-case — it becomes the deployed agent *and* workflow name), one-paragraph `instructions`, the tool list, and the model from step 0.3. Classify each tool: your function → worker tool (`@tool` / `tool()` / `@Tool` / `[Tool]`); HTTP endpoint → `http_tool`; OpenAPI → `api_tool`; MCP server → `mcp_tool(url)`; needs a human decision → `human_tool` (question) or `approval_required=True` (gate a side-effect tool); another deployed agent → `agent_tool`. Ask which tools **write** anything — those get `approval_required=True` or a guardrail (rule F2). Ask for a turn bound (`max_turns`, default 25; 8–12 for unattended agents).
4. **WebFetch before writing code** (Rule 7.3 / Rule 13). Fetch the SDK's `docs/agents/` for the chosen language and the page for the chosen framework; pin the install command, extras and version from what you fetched. Known drifts: Java artifact is `conductor-client-ai`; Python LangChain imports `create_agent` from `conductor.ai.agents.langchain`.
5. **Generate the files** from agent-sdks.md: `agent.<ext>` (definition: `provider/model`, instructions, tools, `max_turns`, optional `credentials=[...]`), `tools.<ext>` (descriptions are the routing contract; idempotency comment; `approval_required` on write tools), `test_<name>.<ext>` (Python `mock_run` + `MockEvent` + `expect`, optional `@pytest.mark.live` `CorrectnessEval`; TypeScript `mockRun` + `expectResult`; Java / C#: assert `plan()` compiles with the expected `requiredWorkers` and say trace assertions are Python/TS only), `run_<name>.<ext>`, `deploy.<ext>` (`plan` then `deploy`; prints `requiredWorkers`), `serve.<ext>` (blocks), `workflows/<name>-invoke.json` (an `AGENT` task with `agentType: "conductor"`, `name`, `prompt`, `pollIntervalSeconds`, `maxDurationSeconds`; add the `waiting` → `HUMAN` → resume-by-`executionId` branch when the agent has a human tool — copy [agent-hitl-resume.json](../skills/conductor/examples/workflows/agent-hitl-resume.json)), `.env.example` (`CONDUCTOR_SERVER_URL`, optional `CONDUCTOR_AUTH_KEY/SECRET`; **no provider keys**).
6. **Verify in this order, showing each command.**
   1. Unit tests (`pytest`, `npx vitest run`, or the repo's runner).
   2. `run` once — print `execution_id` and the UI link `{BASE_URL}/agentExecutions/{execution_id}` (`BASE_URL` = `CONDUCTOR_SERVER_URL` minus `/api`).
   3. `plan` + `deploy`, then `conductor agent get <name>` to confirm registration.
   4. **Agent worker gate (Rule 9).** If `plan()` returned non-empty `requiredWorkers`, or the framework is passthrough (plain LangChain, Claude Agent SDK, complex LangGraph), start `serve` in a separate terminal **before** the next step and say so. Without it executions sit SCHEDULED forever.
   5. `conductor workflow create workflows/<name>-invoke.json`, then `conductor workflow start -w <workflow> --sync -i '{"prompt":"..."}'`.
   6. Observe: `conductor agent execution --name <name> --since 1h`, `conductor agent status <executionId>`, `conductor agent stream <executionId>`; UI `{BASE_URL}/agents`, `{BASE_URL}/agentExecutions/{executionId}`.
7. **Offer next steps** (one line each; do not do them unasked): schedule it (`conductor schedule create -n <name>-<purpose> -c "0 0 2 * * ?" -w <name> -i '{"prompt":"..."}'`), add HITL approval, `/conductor-optimize <name>` against the compiled graph, call it from a `FORK_JOIN` next to another agent.

Rules that apply throughout: `model` is always `provider/model` (Rule 11); `agentType` is only `conductor` / `a2a` / a hosted platform id — never a framework name, and the field is `name`, not `agentName` (Rule 10); `prompt` is required on start **and** resume; approval gates are answered with `conductor agent respond <id> --approve` / SDK `approve()`, never by an `AGENT` resume (Rule 12); secrets go in `credentials=[...]` + the server secret store, never in `instructions`, `prompt`, workflow input or `.env.example` (Rule 5, F5); never recommend `conductor deploy` (Rule 13).
